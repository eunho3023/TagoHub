# 플레이스토어 배포를 위한 서버 구조 설계안

작성 기준: 2026-10-21, 이 저장소의 코드와 오늘 실제로 호출해 본 결과.
**전제:** 약관 확인([api-terms-checklist.md](api-terms-checklist.md))이 끝나기 전에는 어떤 데이터를 서버로 다시 제공해도 되는지 모릅니다.
아래 설계는 "허용된다고 가정했을 때"의 구조이고, 허용되지 않은 데이터는 구조를 바꾸거나 빼야 합니다.

## 1. 지금 구조의 한계 (코드로 확인한 것)

| 문제 | 근거 |
|------|------|
| 키가 APK에 들어가고 모든 사용자가 같은 키를 씀 | `app/build.gradle.kts`가 키를 `BuildConfig`로 넣음 |
| 폰이 공공 API를 직접 부름 → 키 하나의 한도를 모두가 공유 | 각 `*Repository`가 `apis.data.go.kr` 등을 직접 호출 |
| 일부 API는 접속 IP를 제한 (UTIC는 폰에서 JSON 오류) | 오늘 UTIC 오류와 저장본으로 우회한 경험 |
| 일부는 http 전용, 그래서 앱 전체가 http를 허용 | `network_security_config.xml`의 `base-config cleartextTrafficPermitted="true"` |
| 데이터 갱신·저장본·영상 중계가 집 PC 한 대에 의존 | `main.yml`·`overlays.yml`(self-hosted), `tools/cctv_proxy.py` |
| 저장본 호스팅이 GitHub Release | 트래픽·약관 한도가 사용자 수에 따라 문제 |

## 2. 데이터를 세 종류로 나눕니다

변경 빈도에 따라 다르게 다룹니다.

| 종류 | 예 | 갱신 | 제공 방식 |
|------|----|------|-----------|
| **정적** | 정류장·노선 DB, 지하철역, ITS 구간·VDS·결빙, 도로날씨 지점 목록 | 주~월 | 앱에 번들 + 서버에서 내려받아 갱신 |
| **준실시간 스냅샷** | 돌발·재난·CCTV 목록·안전정보·휴게소·영업소·IC·전광판 | 5~10분(안전정보는 12시간) | 정적 파일을 CDN에 올림. **이미 만든 구조**(`build_overlays.py`) |
| **실시간** | 버스·지하철 도착, 차량 위치, 도로날씨 현재값 | 수 초 | 서버가 대신 호출하고 **짧게 캐시**해서 사용자들이 같은 응답을 공유 |
| **스트림** | CCTV 영상 | 연속 | 가장 비쌈. 4번 참고 |

## 3. 목표 구조

```
[앱] ──HTTPS──▶ [CDN/오브젝트 스토리지]  ← 5분마다 갱신 작업이 올림 (정적·스냅샷)
 │
 └──HTTPS──▶ [작은 API 서버 (한국 리전)] ──▶ 공공 API (키는 서버에만)
               · 응답을 5~10초 캐시
               · 앱 인증(Play Integrity 등) + 기기별 호출 제한
               · 접속 IP 제한이 있는 API는 이 서버의 IP를 등록
[갱신 작업 (한국 리전, 항상 켜짐)] ──▶ 공공 API ──▶ 스냅샷 파일 생성
```

- **갱신 작업**은 지금 `overlays.yml`과 `build_data.py`가 하는 일을 항상 켜진 서버로 옮긴 것입니다.
  `README`에 적힌 대로 GitHub 기본 서버는 공공데이터포털이 막을 때가 있어서, **한국 리전**이 필요합니다.
- **CDN/스토리지**는 GitHub Release 대신 쓰는 것을 권합니다(대역폭·이용 한도). 종류는 선택 사항입니다.
- **API 서버**는 실시간 호출 전용이고 상태를 거의 갖지 않아서 작게 시작할 수 있습니다.
- 앱의 `OverlaySnapshot`(메모리 → 폰 저장 → 네트워크, 오래된 것 허용 정책)은 **그대로 재사용**하고 주소만 바꾸면 됩니다.

## 4. CCTV 영상 (가장 큰 결정)

오늘 확인한 사실: 영상 주소는 `http://cctvsec.ktict.co.kr/…` → 302 → `…:8081/…/playlist.m3u8` 형태이고, 한 대당 1Mbps 안팎입니다.

| 선택지 | 장점 | 단점 |
|--------|------|------|
| A. 서버로 중계 | https, IP 비노출 | 사용자×시청 시간만큼 서버 대역폭이 듦 (가장 먼저 비용이 커짐) |
| B. 앱이 직접 재생 | 서버 비용 없음 | http라 `cleartext` 허용이 남음, IP 노출 |
| C. 영상은 빼고 목록·위치만 제공 | 가장 안전 | 기능 축소 |
| D. 제공기관에 정식 이용 협의 | 가장 깔끔 | 시간이 걸림 |

**권고:** 약관 확인 결과가 나오기 전에는 B(현재)를 유지하고, 확인 결과가 "재배포 불가"이면 C 또는 D, "가능"이면 A를 대역폭 상한과 함께.

## 5. 키와 앱 보호

- 공공 API 키는 **서버로 이동**하고 앱에서는 제거합니다(카카오 지도 SDK 키만 앱에 남음 — 키 해시로 보호).
- 앱 → 서버 인증은 Play Integrity 같은 기기·앱 증명을 쓰고, 기기별 호출 제한을 둡니다.
- 서버 응답은 필드를 줄여서(앱이 쓰는 것만) 내려 대역폭과 파싱 비용을 줄입니다.
- **이미 노출된 키 (2026-10-21 커밋 기록 검사 결과):** 저장소가 **공개**입니다. 이 PC의 `local.properties`에 있는 키 값을 모든 브랜치의 커밋 기록에서 찾았습니다.
  - `KRIC_SUBWAY_KEY`만 노출돼 있습니다: `local.properties.example`(2개 커밋)과 저장소 루트의 `subwayRouteInfo.pdf`, `subwayTimetable.pdf` 안에 같은 값이 들어 있습니다.
  - 나머지(`TAGO`, `UTIC`, `ITS`, `EX`, `KMA`, 카카오, 서울, VWorld)는 기록에 없습니다.
  - 예제 파일은 이 커밋에서 자리표시자로 바꿨지만 **기록에는 남습니다**. 할 일: ① KRIC 키 재발급, ② 두 PDF를 저장소에서 빼고(가이드 문서라서 로컬에만 보관), 필요하면 기록 정리(`git filter-repo`)는 이미 공개된 뒤라 재발급이 우선입니다.

## 6. 운영

- **알림·모니터링:** 갱신 작업이 N분 동안 성공하지 못하면 알려야 합니다(지금은 PC가 꺼져 있어도 아무도 모름).
- **저장본 나이 표시:** 앱이 오래된 저장본을 쓰면 "마지막 갱신 N분 전"을 보여줍니다(지금은 30분이 넘으면 API로 넘어가는데, 폰에서 안 되는 API도 있음).
- **공공 API 장애 대응:** 지역별 서버가 자주 불안정합니다(오늘 여수 `04`, 울산 키 미등록). API별 상태를 서버에서 기록하고, 실패가 계속되면 앱에서 해당 지역 기능을 숨깁니다.
- **비용:** 이 문서는 금액을 적지 않았습니다. 사용자 수·영상 시청량이 정해져야 계산할 수 있고, 가장 큰 변수는 4번의 CCTV 영상입니다.

## 7. 단계별 계획

1. **약관 확인** (선행) → 데이터별 사용/조건부/제외 결정
2. **스냅샷을 CDN으로 이전** — 앱은 주소만 바꿈. 가장 위험이 낮음
3. **갱신 작업을 항상 켜진 한국 리전 서버로 이전**
4. **실시간 중계 서버** — 도착정보부터(사용량이 가장 많음), 키를 앱에서 제거
5. **CCTV 방침 확정 후 영상 처리**
6. **플레이 출시 준비** (아래 체크리스트)

## 8. 플레이스토어 출시 체크리스트

코드에서 확인한 현재 상태와, 일반적으로 필요한 것. **정책 기준(특히 targetSdk 최소 버전과 마감일)은 플레이 콘솔 공지로 직접 확인하세요.**

| 항목 | 현재 | 할 일 |
|------|------|-------|
| targetSdk / compileSdk | 34 / 34 | 플레이가 요구하는 최신 기준 확인 후 상향, 동작 변경 점검 |
| 릴리스 최적화(R8) | `isMinifyEnabled = false` | 켜고 실제 기기에서 확인 (Retrofit·XML 해석 코드 보존 규칙 필요할 수 있음) |
| 배포 서명 | 없음 확인(코드에서 `signingConfig` 못 찾음) | 업로드 키 생성·보관, 플레이 앱 서명 사용 |
| 카카오 키 해시 | 개발용 | 배포 서명(플레이 앱 서명 인증서 포함)의 키 해시도 카카오 개발자 사이트에 등록 |
| 번들 형식 | APK 빌드 | 플레이는 AAB 업로드 |
| 네트워크 보안 | 전체 http 허용 | 서버 이전 후 필요한 도메인만 허용 |
| 위치 권한 | `ACCESS_FINE/COARSE_LOCATION` 사용 | 개인정보처리방침 주소, 데이터 보안 설문 작성 |
| 앱 제보 | 깃허브 로그인 필요 | 일반 사용자용 폼·이메일로 교체 |
| 충돌 보고 | 없음 | 도입 (배포 후 문제를 알 수 있게) |
| 테스트 | 단위 테스트 222개, PR 자동 실행 추가 | 비공개 테스트 트랙에서 실제 기기 검증 |
| 공공데이터 출처 표기 | 일부만 | 약관 확인 결과대로 앱 안(정보 화면)에 일괄 표기 |
| 저장소 공개 여부 | 공개 | 키 이력 정리(5번), 필요하면 비공개 전환 검토 |
