# 플레이스토어 배포 체크리스트

코드로 할 수 있는 것은 이미 해 두었고(아래 ✅), 나머지는 **계정·약관·서명 키처럼 직접 하셔야 하는 일**입니다(⬜).
이 문서는 정리용이며 법률 자문이 아닙니다. 정책 요건은 자주 바뀌므로 Play Console 의 정책 센터 안내가 최종 기준입니다.

## 1. 서명 키 (⬜ 직접)

배포용 앱은 내 서명 키로 서명해야 하고, **이 키를 잃어버리면 같은 앱을 업데이트할 수 없습니다.** 안전한 곳에 백업하세요(저장소에 올리지 않음).

```bash
keytool -genkeypair -v -keystore tagohub-release.jks -alias tagohub -keyalg RSA -keysize 2048 -validity 10000
```

저장소 루트에 `keystore.properties` 를 만듭니다(`.gitignore` 에 이미 들어 있어 올라가지 않음):

```properties
storeFile=tagohub-release.jks
storePassword=키스토어_비밀번호
keyAlias=tagohub
keyPassword=키_비밀번호
```

그러면 `./gradlew :app:bundleRelease` 가 서명된 `app-release.aab` 를 만듭니다(✅ 서명 설정을 읽는 코드는 넣어 둠).
Play Console 에서 "Play 앱 서명"을 켜면 업로드 키와 앱 서명 키가 분리되어 더 안전합니다.

## 2. 카카오맵 (⬜ 직접)

카카오 개발자 사이트 → 앱 → 플랫폼 키 → 네이티브 앱 키 → Android 에 **릴리스 키 해시**를 추가 등록해야 지도가 나옵니다.
(디버그 키 해시와 다릅니다. Play 앱 서명을 쓰면 Play Console 의 앱 서명 인증서 SHA-1 로 키 해시를 만들어야 합니다.)

```bash
keytool -exportcert -alias tagohub -keystore tagohub-release.jks | openssl sha1 -binary | openssl base64
```

## 3. API 키 노출 (⬜ 가장 중요)

앱 안에 들어 있는 키(`BuildConfig`)는 APK 를 풀면 누구나 꺼낼 수 있습니다. 난독화(✅ 켬)로는 숨겨지지 않습니다.

- 키마다 **사용 제한**이 걸리는지 확인: 카카오(플랫폼 키는 앱 패키지·키 해시로 제한 가능), 나머지 공공데이터 키는 대부분 제한 기능이 없음
- 공공데이터포털은 개발계정 → **운영계정 전환**을 해야 호출 한도가 늘어납니다(사용자가 늘면 모두가 키 하나의 한도를 같이 씁니다)
- 장기적으로는 키가 필요한 호출을 **내 서버(중계)** 로 옮기는 방법이 안전합니다(지금은 서버가 없어 일부만 집 PC 저장본으로 우회)
- KRIC 키는 공개 저장소 기록에 노출됐으니 **재발급**하세요

## 4. 약관·출처 표기 (⬜ 직접)

`docs/api-terms-checklist.md` 의 표를 채우세요. 특히 앱에 **번들**한 데이터(과속방지턱·어린이보호구역·정류장 DB·도로날씨 지점)와
릴리스로 **재배포**하는 저장본의 이용허락범위(공공누리 유형)를 확인해야 합니다.
앱 안에 출처 표기(제공처 이름)를 넣는 화면이 필요할 수 있습니다.

## 5. 개인정보 처리방침과 데이터 보안 양식 (⬜ 직접 검토)

- 위치 정보를 쓰는 앱은 **개인정보 처리방침 주소**가 필수입니다. `docs/privacy-policy.md` 초안을 검토해 웹에 공개(GitHub Pages 등)한 뒤 그 주소를 Play Console 에 넣으세요. 연락처 칸은 비어 있습니다.
- Play Console "데이터 보안" 양식 답변 초안은 `docs/play-data-safety.md` 에 있습니다.
- 백그라운드 위치는 **쓰지 않습니다**(경로 안내·하차 알림은 앱을 화면에 띄워 시작하는 포그라운드 서비스).

## 6. 기술 요건 (⬜ 확인 필요)

| 항목 | 현재 | 할 일 |
|---|---|---|
| 대상 API 수준(targetSdk) | 34 | Play 는 새 앱·업데이트에 최신에 가까운 targetSdk 를 요구합니다. **정책 센터에서 현재 요구 수준을 확인**하고, 올릴 때는 compileSdk·AGP 도 함께 올리고 화면(엣지 투 엣지 등)을 다시 확인해야 합니다. 이번에는 시험할 기기가 없어 올리지 않았습니다 |
| http(암호화 안 됨) 통신 | 일부 허용 | 서울·제주·UTIC·ITS CCTV 가 http 만 제공해서 `network_security_config.xml` 에서 허용. 정책상 문제가 되지는 않지만 심사 시 설명이 필요할 수 있음 |
| 코드 축소·난독화 | ✅ 켬 | **릴리스 빌드를 실제 폰에서 꼭 시험** (난독화 때문에 생기는 오류는 컴파일로는 안 잡힘). 배포마다 `mapping.txt` 보관 |
| 자동 백업 | 켜짐 | 즐겨찾기·집/회사가 구글 백업으로 옮겨짐 (처리방침에 적음). 큰 저장본까지 백업되지 않게 제외 규칙을 넣을 수 있음 |
| 오류 수집 | 없음 | 출시 후 오류를 알려면 Firebase Crashlytics 같은 도구 필요(계정·개인정보 처리방침 갱신 필요) |
| 테스트 | 단위 테스트만 | 개인 개발자 계정은 **비공개 테스트 요건**이 있을 수 있음 → Play Console 안내 확인 |

## 7. 스토어 등록 정보 (⬜ 직접)

앱 이름·간단/자세한 설명, 스크린샷(폰), 아이콘(512px), 대표 이미지(1024x500), 콘텐츠 등급 설문, 연락처 이메일, 개인정보 처리방침 주소.
"교통 정보를 보여주는 참고용이며 실제 운행·도착 시각과 다를 수 있다"는 안내를 설명에 넣는 것을 권합니다.
