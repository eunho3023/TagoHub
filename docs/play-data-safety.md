# Play Console "데이터 보안" 양식 답변 초안

앱의 현재 동작(2026-10-22 기준)에서 나온 **초안**입니다. 양식의 질문 문구는 Play Console 에서 바뀔 수 있으니 하나씩 읽고 확인하세요.
2026-10-29 갱신: 앱에 **Firebase 익명 로그인 + 선택 구글 로그인, Firestore 동기화, 앱 제보(reports)** 가 들어갔습니다. 광고·분석 도구는 없습니다. 기능을 더 넣으면 답을 다시 해야 합니다.
2026-11-02 갱신: 선택 로그인에 **이메일(비밀번호·이메일 링크)과 전화번호**가 늘었고, **검색 기록·경로 기록**도 클라우드에 올라갑니다. 아래 "수집하는 데이터 유형" 답에 이메일·전화번호·검색 기록·경로 기록이 들어 있는지 확인하세요.

| 질문 | 답 | 근거 |
|---|---|---|
| 앱이 사용자 데이터를 수집하거나 공유하나요? | **예** (위치, 이메일, 전화번호 등) | 아래 참고 |
| 수집하는 데이터 유형 | **위치 → 대략적인 위치, 정확한 위치**(길찾기 때 카카오로 전달) / **위치 → 집·회사 좌표, 경로 기록의 출발·도착 좌표**(Firestore 저장) / **개인 정보 → 이메일 주소**(이메일·구글로 가입·연결한 경우) / **개인 정보 → 전화번호**(전화번호로 로그인한 경우) / **앱 활동 → 앱 내 검색 기록**(검색 기록) / **앱 활동·사용자 콘텐츠 → 앱 제보 내용** / **기기 또는 기타 ID → 익명 사용자 ID** / **앱 정보 및 성능 → 기기 모델·안드로이드·앱 버전**(제보에 포함) | 내 위치 표시·길찾기·안내, 로그인·계정, 설정·기록 동기화, 제보 |
| 그 외(이름, 사진, 연락처, 광고 ID, 결제 등) | 수집 안 함 | 해당 기능 없음 |
| 구글(Firebase)로 보내는 데이터 | **수집**으로 신고, 목적은 **앱 기능·계정 관리**. Firebase 는 개발자의 처리 서비스 제공자라 "공유"에서 제외되는 규정에 해당하는지 Play 정의를 읽고 확인 | 확인 필요 |
| 위치는 **수집**인가 **공유**인가 | 개발자 서버로 보내지 않음. 길찾기·검색을 위해 **카카오 등 서비스 제공처로 좌표가 전달됨** → 서비스 제공 목적의 전달로 보고 "공유" 여부는 **Play 정의를 읽고 판단** (처리 서비스 제공자에게 보내는 경우는 공유에서 제외되는 규정이 있음) | 확인 필요 |
| 데이터 처리 목적 | 앱 기능(내 위치, 길찾기, 안내, 알림) | |
| 선택 사항인가 | **예**: 위치 권한을 거부해도 지도·정보 조회는 가능 | |
| 전송 중 암호화 | **Firebase·카카오 호출은 https. 일부 공공 API 만 http 라 전체로는 "아니오"로 답할 수 있음**: 서울·제주·UTIC·ITS CCTV 는 http 만 제공. 위치 좌표를 보내는 카카오 호출은 https | `network_security_config.xml` |
| 사용자가 데이터 삭제를 요청할 수 있나요 | **예** — 앱 안: 설정 → 계정 → "내 데이터 삭제"(클라우드 설정 문서·로그인 계정·기기 동기화 항목 삭제). 앱 제보는 이메일 요청. Play 가 요구하는 **웹 삭제 안내 주소**는 공개한 개인정보 처리방침 페이지의 4항 주소를 쓰면 됨 | 처리방침 공개 후 주소 입력 |
| 백그라운드 위치 | **사용 안 함** | 포그라운드 서비스만 |

민감 권한 신고: 위치(포그라운드). 포그라운드 서비스 유형 `location` 사용 이유를 묻는 양식에는
"사용자가 시작한 경로 안내·하차 알림이 화면을 꺼도 계속되도록"이라고 쓰고, 시연 영상을 요구하면 앱에서 안내를 시작해 알림이 뜨는 장면을 찍어 올립니다.

참고: **출근 알림**을 켜면 앱이 알림 시각 무렵 백그라운드에서 저장한 집·회사 좌표로 카카오 길찾기를 호출합니다(기기의 현재 위치는 쓰지 않음). 위 "위치 공유" 답변을 정할 때 이 호출도 포함해서 판단하세요.
