# TagoHub — TAGO(1613000) 통합 교통 앱

국토교통부 TAGO와 KRIC 철도 Open API 등 공공 교통 API를 하나의 앱으로 묶었습니다.
Kotlin + Jetpack Compose + Retrofit, 패키지 `com.eunho.tagohub`.
TagoTransit 과 같은 규칙(`BuildConfig.TAGO_SERVICE_KEY`, `TagoResult`, HTTP/1.1 강제, 페이지 크기 폴백)을 따르므로 모듈 단위로 옮겨 붙일 수 있습니다.

## 실행

1. `local.properties` 에 `TAGO_SERVICE_KEY=...` 추가 (Encoding/Decoding 키 둘 다 가능)
2. 열차별 도시철도 운행정보를 쓰려면 `KRIC_SUBWAY_KEY=...` 도 추가
3. UTIC 교통정보 링크를 쓰려면 `UTIC_API_KEY=...` 도 추가
4. Android Studio 에서 열고 실행 (minSdk 26, AGP 8.5.2, Kotlin 2.0.20)

data.go.kr 은 서비스마다 활용신청이 따로입니다. 화면에 "서비스 접근 거부 (코드 20)" 이 뜨면 해당 서비스 신청 상태를 확인하세요:
버스정류소정보 · 버스노선정보 · 버스위치정보 · 버스도착정보 · 지하철정보 · 열차정보 · 국내항공운항정보 · 고속버스정보 · 시외버스정보 · 고속버스도착정보

## 실시간 위치·노선 표시 방식

- **새로고침 버튼**(지도 오른쪽 위): 열린 정류소 도착정보, 노선 버스 위치, 역 도착정보, 실시간 열차, 주변 정류소를 즉시 다시 받습니다.
- **노선을 도로에 맞춰 그리기**: TAGO 는 정류소 좌표만 줘서, 정류소를 차례로 잇는 도로 경로를 OSRM(OpenStreetMap 경로 탐색)
  공개 서버에서 받습니다(`RoadShapeClient`, 25개씩 나눠 요청, 노선별 캐시). 실패하거나 직선거리의 3배 넘게 돌아가는 구간은 직선으로 둡니다.
  공개 데모 서버라 배포용으로는 자체 OSRM 서버나 상용 길찾기 API 로 바꾸는 게 좋습니다.
- **지역 자동 판별**: 검색할 때 지역을 고르지 않아도 됩니다. 지도 중심 근처 정류소의 도시코드로 지역을 정하고, 지역 버튼으로 직접 바꿀 수도 있습니다.
- **버스 위치 보정**: TAGO 버스 위치 좌표는 실제 GPS 가 아니라 "지난 정류소" 좌표입니다. 그래서 정류소를 처음 지난 시각부터
  평균 20km/h 로 다음 정류소 쪽으로 도로를 따라 움직이고, 다음 정류소 92% 지점에서 다음 갱신을 기다립니다. 위치 10초, 도착정보 15초마다 갱신하며
  도착 시간은 그 사이 매초 줄어듭니다. 응답에서 잠깐 빠진 버스는 2번까지 직전 위치를 유지합니다.
- **열차 이동**: 서울 API 의 역·상태(진입/도착/출발/전역출발)와 수신 시각으로, 행선지 방향의 이전·다음 역을 추정해 평균 40km/h 로 움직입니다.
- 새 데이터로 위치가 바뀌면 순간이동하지 않고 1.2초 동안 미끄러지듯 따라갑니다.

| 탭 | 사용 API | 기능 |
|---|---|---|
| 지도 | 브이월드 + TAGO 버스 + 서울 실시간 지하철 + 도시철도역사 표준데이터 | 버스: 확대 시 주변 정류소, 정류소 → 도착정보, 노선 → 경로 + 실시간 버스(15초). 지하철: 전국 역 마커(환승역 묶음), 수도권 실시간 열차 위치(30초), 역 → 실시간 도착(20초). 위성지도·야간지도 |

지도 CCTV 위치 표시는 제거했습니다. 지도 레이어 메뉴의 **UTIC 돌발정보**를 켜면 UTIC 돌발정보 XML의 경도·위도 좌표를 지도 마커로 표시하고, 마커를 눌러 상세 내용을 볼 수 있습니다. 지도 이동 시 캐시된 결과를 화면 범위에 맞춰 보여주며 API 요청은 최대 1분에 한 번으로 제한합니다. UTIC 가이드가 CCTV 목록의 반복 수집을 금지하므로 CCTV 위치는 지도에서 가져오지 않습니다. 나머지 데이터는 메뉴의 **UTIC 교통정보**에서 원본을 열 수 있습니다.

## 지도 (OSMDroid + 브이월드)

TagoTransit 과 같은 구성입니다. WebView·OpenLayers·국토정보플랫폼은 모두 제거했습니다.

- 타일: 브이월드 **TMS** `https://api.vworld.kr/req/tms/1.0.0/{키}/{Base|Satellite}/{z}/{TMS y}/{x}.{png|jpeg}`
  (TagoTransit 에서 브라우저로 서울 타일 `.../Base/11/1254/1746.png` 을 확인한 형식. `VWorldTileSource`, 단위 테스트로 고정)
- 키: `local.properties` 의 `VWORLD_API_KEY`
- 키가 없거나 10초 안에 타일이 한 장도 안 오면 OpenStreetMap 으로 바꾸고 화면 위에 이유를 표시합니다.
  타일 상태는 Logcat 태그 `TagoMap` 에 남습니다.
- 지도 종류(레이어 버튼): 기본지도(Base) · 백지도(white) · 야간지도(midnight) · 위성지도(Satellite + 도로명 Hybrid 겹침).
  브이월드 TMS 문서 표대로 white·midnight 는 최대 18레벨(그 이상은 확대 표시), Satellite 만 jpeg.
  다크모드에서는 처음에 야간지도, 고른 종류는 버스·지하철 탭이 같이 기억합니다.
- 정류소·역·노선·차량은 OSMDroid Marker 대신 직접 그리는 레이어(`MapLayers.kt`)라 역 1,100개도 가볍습니다.

## 탭 구성

같은 지도 화면(`MapScreen`)을 `MapMode` 로 레이어만 바꿔 씁니다. 탭마다 ViewModel 이 따로라 상태가 섞이지 않습니다.

- **버스** (지도 + 버스): 정류소명·정류소번호·노선번호를 지역 선택 없이 검색 (지도 위치로 지역 자동 판별). 지도를 확대하면 주변 정류소 자동 표시.
  정류소 → 도착정보(15초, 매초 카운트다운), 노선 → 도로를 따라 그린 경로 + 실시간 버스(10초, 계속 이동) + 아래 패널에 정류소 타임라인.
- **지하철**: 역·실시간 열차만 (아래 설명)
- 기차 / 고속·시외 / 항공: 시간표

### 지하철 탭

지도 탭과 같은 지도 화면을 **버스 레이어 없이** 별도 인스턴스로 띄웁니다 (`MapScreen(subwayOnly = true)`).
위쪽 검색창은 내장 역 데이터를 바로 검색하고, 고르면 지도가 그 역으로 이동하며 상세가 열립니다.

역 상세(`StationDetailPanel`)는 지도 탭에서 역을 눌러도 똑같이 열립니다.
- **실시간 도착**: 서울 `realtimeStationArrival` (수도권 노선만)
- **시간표·출구정보**: TAGO `SubwayInfo`. 표준데이터 역과 TAGO 역을 이름+노선으로 연결합니다
  (`StationName.sameLine`: TAGO "경의중앙"↔"경의중앙선", "공항"↔"공항철도"). 환승역이면 노선 칩으로 고릅니다.
  노선이 하나도 안 맞으면 이름이 같은 TAGO 역을 모두 보여줍니다.
- 시간표의 **열차별** 보기와 **노선** 탭은 KRIC `trainUseInfo` API 를 사용합니다. TAGO 역 검색 응답에 KRIC 노선 코드가 빠져 있는 경우 KRIC 전체노선정보에서 역 코드를 먼저 확인합니다. `KRIC_SUBWAY_KEY` 가 없으면 해당 화면에 설정 안내가 표시되고 TAGO 시간표는 계속 이용할 수 있습니다.
- 표준데이터에 없는 노선(예: GTX-A)은 서울역 같은 환승역 상세에서 시간표 노선 칩에 나오지 않습니다.

### 지하철 (지도)

- **역 위치**: `assets/subway_stations.tsv` (전체_도시철도역사정보_20260630.xlsx 에서 변환, 1,099개 역). 같은 이름이고 500m 안에 있는 역은 마커 하나로 묶고, 환승역은 회색 테두리.
- **실시간 열차**: 서울 `realtimePosition`. 화면 안에 역이 있는 노선만 30초마다 조회하고, 지도 탭을 떠나면 멈춥니다(일일 호출 한도 보호). 열차 버튼으로 끌 수 있습니다.
  위치는 GPS 가 아니라 역 단위(진입/도착/출발)라 해당 역 좌표에 표시하고, 상·하행은 약 25m 비켜서 겹치지 않게 했습니다.
- **역 도착정보**: 서울 `realtimeStationArrival`. 같은 이름의 다른 역(양평 5호선/경의중앙선) 결과는 노선으로 걸러냅니다. `barvlDt` 는 수신 시각 기준이라 경과 시간을 빼서 보여주고, 0 이면 `arvlMsg2` 문구를 씁니다.
- **노선 매핑** (`SeoulLines`): 서울 API 1호선 = 표준데이터 1호선·경부선·경원선·경인선·장항선, 3호선 = 3호선·일산선, 4호선 = 4호선·안산과천선·진접선, 수인분당선 = 분당선·수인선 등.
- **역명 정규화**: 괄호 제거 + "역" 접미사 제거 (`청량리(서울시립대입구)`, `서울역(경의선)`, `서울역` → 각각 `청량리`, `서울`).
- 서울 API 는 http 만 제공 → `res/xml/network_security_config.xml` 에서 `swopenapi.seoul.go.kr` 만 HTTP 허용.
- 데이터 정리: 원본에 `북구청\n(대구iM뱅크파크)` 처럼 줄바꿈이 든 역명이 있어 공백을 정리했습니다.
- 실시간 미지원 노선: 인천 1·2호선, 의정부, 에버라인, 김포골드라인, 지방 도시철도 → 역 마커와 시간표만.





### 전주 시내버스: 전주시 버스정보 API + 길찾기·환승

전주 정류장·노선(ID 가 `JUB` 로 시작)은 전주시 버스정보 API(apis.data.go.kr/4641000)를 씁니다. 키는 TAGO 와 같은 `TAGO_SERVICE_KEY`.
전주 표준 ID 9자리 = TAGO ID 에서 `JUB` 를 뗀 값이라 내장 정류장 DB 와 그대로 연결됩니다(PDF 응답의 정류장 119개 모두 일치 확인).

| 용도 | API | 파라미터 |
|---|---|---|
| 정류장 도착 | realtime/bus_location_busstop_infomation_common | stopStdid |
| 노선 정류장 목록 + 버스 위치 | realtime/bus_location_bus_position_common | brtStdid |
| 노선 모양 | nosun/bus_nosun_drawing_common | brtStdid |
| 환승 경로 | transfer/fromto_bus_search_transfer_detail_common | sStandardId, eStandardId, maxCnt |

- 도착정보에 버스가 지금 있는 정류장·방면이 함께 나옵니다. 노선 모양은 전주시가 주는 실제 선형(WGS84)으로 그립니다.
- 전주시 API 가 실패하면 TAGO 로 대체합니다. 응답 형식: `<RFC30><code>000</code>…<routeList><list>…`
- **길찾기** (버스 탭 검색창 옆 버튼): 목적지를 장소 이름(브이월드 검색 API, 같은 VWORLD_API_KEY) 또는 정류장 이름으로 고르면
  - 출발지(내 위치, 없으면 지도 중심, 직접 지정 가능)와 도착지 600m 안의 전주 정류장을 찾고
  - **직통**: 출발 정류장을 지나는 노선의 정류장 목록에서 도착 정류장이 뒤에 나오는 노선
  - **가까운 환승 (앱에서 계산)**: 출발 정류장을 지나는 노선의 하류 정류장과, 도착 정류장을 지나는 노선의 상류 정류장이
    같은 정류장이거나 200m 안에서 만나는 지점을 모두 비교해 노선 조합마다 가장 빠른 곳 하나 (격자 검색이라 빠름)
  - **전주시 환승 경로검색**도 함께 받아서, 노선 좌표로 실제 거리를 다시 계산해 비교
  - 예상 시간 = 걷기(72m/분) + 버스(노선을 따라 실제 거리 ÷ 18km/h + 정류장당 0.3분) + 환승 4분 + 환승 걷기 + 첫 버스 대기(실시간)
  - **크게 돌아가는 경로 제외**: 버스로 가는 거리가 출발·도착 직선거리의 2.5배를 넘으면, 괜찮은 대안이 3개 이상 있을 때 뺀다
  - 경로를 누르면 지도에 걷기(점선)·버스 구간(노선 모양을 잘라서)·출발/환승/도착 표시, 첫 버스와 환승 버스의 실시간 도착을 20초마다 갱신
- 전주시 API 의 tripTime·tripDistance 는 정류장 수와 맞지 않는 값이라 쓰지 않고, 정류장 수(RStop1·RStop2)로 시간을 계산합니다.
- 테스트: `JeonjuTest` (PDF 실제 응답으로 도착·노선·모양·환승·직통 검증)


### 정류장 도착 표시·시간표·버스 움직임 (카카오맵 방식)

- **정류장 도착**: 노선마다 빠른 순으로 두 대. 10분 안쪽은 초까지 ("4분 53초 (5개 전)"), 두 번째 차가 없으면 "정보없음". 매초 줄어듭니다.
  노선 종류 배지(일반·순환 = 전주 brtClass 0/1), 방향, 버스가 지금 있는 정류장. 노선을 누르면 지도에 노선 + 실시간 버스.
- **예상 시간표** (정류장 패널의 "시간표"): 평일·토요일·일요일 → 노선 → 이 정류장에 서는 예상 시각을 시(時)별로, 다음 차 강조.
  - 평일: `nosun/bus_location_time_common` 의 운행별 출발 시각 + 출발 정류장(startSeq)부터 이 정류장까지 소요시간(노선 정류장 거리로 계산)
  - 주말: `nosun/bus_location_busstop_info_common` 의 satNlist / holiNlist (첫 정류장 출발)
  - 이 두 API 의 요청 파라미터 이름은 확인되지 않아 `brtStdid`·`brtStdId`·`stdId` 를 함께 보냅니다(모르는 파라미터는 무시됨). 응답이 비면 시간표만 안 나옵니다.
- **노선 패널**: 정류장마다 첫차·막차 예상 시각 ("07:24 - 23:12"), 버스가 있는 정류장에 차량번호.
- **버스 움직임 = TAGO 실시간 GPS** (전주 포함)
  - 2026-10-10 캡처로 확인: 전주 3-1번에서 정류장 순번이 그대로인 1394번(27→27)·1402번(46→46)도 좌표가 42m·55m 바뀜
    → TAGO `getRouteAcctoBusLcList` 의 gpslati/gpslong 은 정류장 좌표가 아니라 실시간 차량 GPS. 정류장 순번도 전주시 API 와 같음.
  - 그래서 버스 위치는 모든 노선에서 TAGO GPS 를 먼저 쓰고, 안 될 때만 전주시 API(정류장 단위)를 씁니다.
  - 새 위치를 받으면 직전 위치에서 새 위치까지 **노선 모양(도로)을 따라**, 위치가 바뀌는 데 실제 걸린 시간(5~30초) 동안 따라갑니다.
  - **새 위치가 8m 안에서 그대로면 지도에서도 그 자리에 멈춰 있음** → 신호 대기·정체·정류장 정차 그대로 반영.
  - **앞뒤로 왔다 갔다 하지 않게** (`GpsTracker`): TAGO 는 나중 요청에 더 옛날 위치를 주기도 함
    (사용자 캡처: 12:40:50 응답이 12:40:42 응답보다 한 정류장 뒤). GPS 점을 노선 모양 위에 올려 진행 거리로 바꾸고,
    이미 간 곳보다 15m 넘게 뒤인 위치는 무시. 3번 연속 뒤로 오면 실제라고 보고 바로 옮김(뒤로 미끄러지지 않게).
    노선 모양에서 위치를 찾을 때 버스가 알려준 정류장 순번 앞뒤 구간만 봐서 양방향 도로에서 반대편에 붙지 않음.
    정류장 순번이 노선 절반 넘게 줄면 새 운행 시작으로 보고 바로 옮김.
  - **노선 선을 벗어나지 않게**: GPS 좌표를 노선 선(노선 모양, 없으면 정류장을 이은 선) 위 가장 가까운 점으로 붙여서 그림 (`RouteGeom.snap`).
    버스가 알려준 정류장 순번 앞뒤 구간에서만 찾아 반대 방향 도로에 붙지 않음. 이동도 선의 꼭짓점을 따라감.
  - **실시간 GPS 판별**: 지역에 따라 TAGO 가 GPS 대신 정류장 좌표를 줌(정류장에 닿을 때만 바뀜). 같은 정류장 순번에서
- **상·하행 나란히** (`RouteDirections` + `OffsetLine`): 같은 도로를 오가는 노선은 방향별 선을 진행 방향 오른쪽으로 4dp 씩 띄워
  나란히 그림 (우측통행이라 실제 버스가 다니는 쪽). 화살표도 각자 자기 선 위에. 회차점: TAGO 방향코드(updowncd) / 경기 turnYn /
  순환 노선은 기점에서 가장 먼 정류장. 노선 패널 정류장 목록에는 회차 정류장 뒤에 회차 표시.
  노선 패널의 "○○ 방면" 버튼: 패널 정류장 목록을 그 방향으로 바꾸고, 지도에서는 그 방향 선을 진하게·반대 방향을 흐리게.
  정류장에서 노선을 열면 그 정류장 방향이 먼저 선택됨. 버스는 양방향 모두 표시.
- **노선 진행 방향 화살표**: 노선 선 위에 약 70dp 간격으로 › 표시 (노선 정류장 순서 방향).
  - **버스는 뒤로 가지 않음** (세 겹):
    1) `StaleGuard`: 모든 버스 위치(TAGO·전주·제주·경기)에서 정류장 순번이 줄어든 옛 응답은 직전 위치 유지, 3번 연속이면 받아들임, 노선 절반 넘게 줄면 새 운행
    2) `GpsTracker`: GPS 가 노선 위에서 조금이라도 뒤면(오차·시차) 그 자리, 15m 넘게 뒤면 옛 데이터로 보고 3번 연속일 때만 옮김.
       정류장에서 25m 넘게 떨어진 좌표면 처음부터 실시간 GPS 로 판단 → 추정에서 GPS 로 바뀔 때 뒤로 튀지 않음
    3) 지도 레이어: 새 경로 위에서 이미 앞서 보이고 있으면 거기서 이어가고, 도착점보다 앞이면 그 자리에서 기다림
  - 카카오맵 "초정밀 버스"는 버스 단말기 GPS 를 1~2초 간격으로 제휴로 받는 방식이라, 공공 API(10~30초, 지역에 따라 정류장 단위)로는 같은 정밀도를 낼 수 없음


### 같은 정류장의 다른 시군 버스

시군 경계 근처 정류장은 시군마다 따로 등록돼 있습니다(예: 전주 BYC `JUB312100690` ↔ 김제 BYC `TSB311000313`, 1m).
전주 정류장 2,913곳 중 216곳이 김제·임실·진안·완주 등 다른 시군 정류장과 겹칩니다.
정류장을 누르면 내장 DB 에서 다른 시군 정류장 중 **시군마다 가장 가까운 하나(30m 안)**를 찾아
그 도착정보·경유노선도 같은 목록에 지역 이름과 함께 보여줍니다. 같은 이름이라도 20~30m 떨어진 정류장은 대개 길 건너편(반대 방향)이라
시군마다 가장 가까운 것만 씁니다. 노선을 누르면 그 시군 도시코드로 노선을 엽니다.

지도 마커·검색 결과에서도 이런 정류장은 **하나로 합칩니다** (`StopMerge`). 서로가 서로의 가장 가까운 다른 시군 정류장일 때만 묶어서
길 건너편 정류장은 섞이지 않습니다. 대표는 지금 보고 있는 지역 정류장이고, 번호는 모두 보여줍니다 (예: `30690 · 3110313`).

정류장 패널 머리: **번호 · ○○ 방면**. 방면은 이 정류장을 지나는 노선들의 바로 다음 정류장 중 가장 많이 나온 이름 (카카오맵과 같은 방식).


### 제주 버스: 제주 BIS OPEN API (TAGO 대신)

제주 정류장·노선(ID 가 `JEB` 로 시작, 도시코드 39)은 TAGO 대신 제주 버스정보 OPEN API(`http://bus.jeju.go.kr/api/…`, JSON, 인증키 없음)를 씁니다.
제주 ID 9자리 = TAGO ID 에서 `JEB` 를 뗀 값 (예: 406000191 ↔ JEB406000191 앞동산[남], 내장 DB 와 일치 확인).

| 용도 | API | 파라미터 |
|---|---|---|
| 정류장 도착 (분·남은 정류장·차량번호·현재 위치·저상) | searchArrivalInfoList.do | station_id |
| 정류장 경유 노선 | searchRouteByStationList.do | station_id |
| 노선 경유 정류장 | searchBusRouteStationList.do | route_id |
| 버스 위치 (전체 버스 GPS) | searchBusAllocList.do | - |
| 노선 목록 (검색·첫차·막차·배차) | searchBusRouteList.do | - |

- 응답 JSON 의 감싼 구조는 가이드에 없어서, 필드명(ROUTE_ID·STATION_ID)을 가진 배열을 어디에 있든 찾아 씁니다 (`MiniJson.findRows`).
- 노선 정류장 좌표: 내장 DB → 없으면 OpenAPI 정의서 Ver2.0 의 `busopen.jeju.go.kr/OpenAPI/service/bis/Station`(XML) 좌표로 보충.
- 버스 위치는 GPS 라 전주처럼 같은 정지 감지·도로 따라 이동·옛 데이터 무시 규칙이 그대로 적용됩니다. 응답에 정류장 순번이 없어서 최근 정류장을 노선 정류장 목록에서 찾아 붙입니다.
- http 주소가 https 로 넘어가는 경우도 있어 http 실패 시 https 로 재시도. 두 주소 모두 http → network_security_config 에 허용.
- **인증서 오류 대응**: 제주 서버는 https 인증서의 중간 인증서가 빠져 있어 안드로이드에서 `Trust anchor for certification path not found` 가 남.
  제주 클라이언트에만 `AiaTrustManager`(X509ExtendedTrustManager)를 붙여, 연결에서 서버 이름을 꺼내
  `X509TrustManagerExtensions.checkServerTrusted(chain, authType, host)`(도메인별 보안 설정이 있는 앱에서 안드로이드가 요구하는 방식)로 검증하고, 실패하면 인증서의 AIA(caIssuers) 주소에서 중간 인증서를 받아
  체인을 채운 뒤 **다시 기기의 기본 검증**으로 확인 (검증을 끄는 게 아님, 호스트 이름 검사도 그대로).
  테스트: 직접 만든 루트→중간→서버 인증서로 실제 PKIX 검증 (`AiaTrustTest`). 엉뚱한 인증서를 받아오면 계속 거부.
  중간 인증서 주소(AIA)는 보통 http 인데 안드로이드가 허용 목록 밖 http 를 막아서, 소켓으로 직접 받는다(`PlainHttp`).
  받는 것이 서명된 공개 인증서라 위·변조돼도 검증에서 걸러진다.
  그래도 실패하면 화면에 http·https 각각의 원인과 인증서 진단(서버 인증서 발급자, 중간 인증서 주소·받기 결과, 보충 후 최상위)을 표시.



### 경기 버스: 경기도 GBIS v2 (TAGO 대신)

경기 정류장·노선(ID 가 `GGB` 로 시작)은 TAGO 대신 경기도 버스정보 GBIS v2(`https://apis.data.go.kr/6410000/…`, format=json, 같은 서비스키)를 씁니다.
경기 ID 9자리 = TAGO ID 에서 `GGB` 를 뗀 값 (가이드 예시 233001450·200000078·200000177 모두 내장 DB 와 일치, 경기 정류장 45,667곳).

| 용도 | API | 파라미터 |
|---|---|---|
| 정류소 도착 (차량 2대, 초 단위, 위치 정류소, 저상) | busarrivalservice/v2/getBusArrivalListv2 | stationId |

| 노선 형상 | busrouteservice/v2/getBusRouteLineListv2 | routeId |
| 버스 위치 (정류소 순번 + 도착/출발/교차로통과) | buslocationservice/v2/getBusLocationListv2 | routeId |

- **실제 응답 확인 (2026-10-12)**: 노선 목록("12" 검색 46개), 노선 정보(98번), 노선 정류장(97곳, 회차점 50번 청담초등학교앞), 노선 형상(721점)으로 테스트(`GbisRealTest`).
  응답이 XML 로 와도 읽도록 `GbisParser` 가 JSON·XML 모두 처리 (전에는 XML 이면 실패했음). 게이트웨이 오류(키 미등록)도 메시지로.

- 노선번호 검색은 경기 시군별 TAGO 조회 대신 GBIS 한 번 → 검색 호출이 크게 줄어듦.
- 버스 위치에 GPS 좌표가 없어 지도에는 그리지 않고, 노선 패널 정류장 목록에 몇 번째 정류장인지만 표시.
- 경기 일반형시내버스는 초록색. GBIS 실패 시 TAGO 로 대체.

- **노선** 7,239개 (`routes` 표): 이 노선이 있는 52개 지역은 노선번호 검색을 TAGO 대신 앱 안 목록으로(서버 호출 없음). 노선 정보·경유노선의 기점·종점 이름도 이 데이터.
- **도시코드**: 교통안전공단 지자체코드 → TAGO 도시코드는 기존 TSB 정류장으로 학습(61개 지자체).
  대응이 없는 곳(전주시 안 등)은 별도 코드 `TS`+지자체코드로 넣어 같은 시 정류장과 합쳐질 수 있게 하고,
  TAGO 요청 때는 TAGO 주변 정류장에서 실제 도시코드를 찾아 씀(없으면 이름으로 맞춘 `city_alias` 표).
- 파일에 정류장 순서·실시간 정보는 없어서 노선 정류장 목록·도착·버스 위치는 계속 TAGO.


### 다른 시군 버스·방면·시간표 버스 선택

- **TSB 정류장은 시군마다 조회**: TSB(교통안전공단) 정류장은 노선을 운영하는 시군의 도시코드로 조회해야 그 시군 버스가 나옴.
  후보(TAGO 주변 정류장의 코드, 이름 대응표, 근처 TSB 시군 7곳)를 경유노선으로 확인해 노선이 나오는 시군을 모두 조회하고, 지역 이름과 함께 한 목록에.
  (예: 기린대로 병무청 3050070 → 근처 후보 김제·임실·익산·진안·정읍… 중 임실 농어촌버스 752·203 등이 나오는 시군)
  처음 한 번만 확인하고, 이후 갱신은 확인된 시군만.
- **방면은 회차 노선만**: 첫·끝 정류장이 같거나 300m 안인 노선만 상·하행 "○○ 방면" 버튼·목록의 방면 표시. 편도 노선(예: 119 평화동종점→전주대학교)은 기점-종점만.
- **노선 종류 배지**: 전주 4자리(4000·6002) = 간선, 3-2 등 brtClass 1 = 순환, 그 외 일반, 교통안전공단 노선 = 농어촌(주황).
- **시간표 버스 선택**: 지금 고른 버스(배지 + 번호(기점-종점))를 누르면 "버스 선택" 시트에서 고름, 고른 버스에 체크.

### 버스·지하철 한 지도 + 정류장 표지판 마커

- 버스 탭과 지하철 탭을 **"버스·지하철" 탭 하나**로 합침 (`MapMode.Transit`): 정류장·지하철역·실시간 버스·실시간 열차를 한 지도에.
  역 마커를 누르면 역 패널(실시간 도착·시간표·출구), 정류장 마커를 누르면 정류장 패널. 열차 표시 켜기/끄기 버튼은 그대로.
- 검색창 하나로 정류소·노선번호·**지하철역**까지 (지하철역은 앱 안 데이터).
- 버스 정류장 마커: 원 → **정류장 표지판 모양** (짧은 기둥 위 둥근 사각 표지판 15dp + 흰 버스 그림, 기둥 끝 = 정류장 위치, 선택하면 1.35배).
  이름표는 표지판 위, 누르는 범위는 표지판 가운데 기준. 지하철역은 사각형 그대로, 내 위치는 원 그대로.

### 길찾기: 다른 지역까지, 정류장 범위 넓히기

- 출발지·도착지 근처 정류장을 600m → 1.2km → 2km 로 넓혀가며 경로가 나올 때까지 찾음 (걷는 거리는 예상 시간에 포함되어 먼 정류장은 뒤로).
- 전주 시내버스만이 아니라 모든 지역 정류장·노선(농어촌·시외 포함) 사용: 노선·정류장 순서·첫 버스 도착은 지역별 출처
  (앱 안 데이터 → 휴대폰 저장 → 지역 API/TAGO), 전주 정류장끼리는 전주시 환승 경로검색도 함께.
- 예: 전주에서 김제·완주·임실로 가는 길 (전에는 도착지 600m 안에 전주 정류장이 없어서 경로가 안 나왔음).

### 서버 호출 줄이기 (API 없어도 되는 것 제거)

- **TAGO 주변 정류장 검색 제거**: 같은 자리 다른 시군 정류장 찾기, 교통안전공단 정류장의 도시코드 찾기, TSB 시군 후보 — 모두 앱 안 정류장 데이터만
  (교통안전공단 파일로 전주시 안 정류장까지 들어 있음). 정류장 DB 를 못 열었을 때의 대체 경로에만 남김.
- **휴대폰에 저장 (`StaticCache`, 기한 없음)**: 한 번 받으면 계속 사용 (filesDir/static_cache). 앱을 업데이트하면(versionCode 가 바뀌면) 한 번 비우고 새로 받음 → 노선 개편이 반영된 새 앱에서 예전 노선이 남지 않음.
  - 노선 모양 (서울·경기·전주 API, 외부 길찾기 OSRM)
  - 노선 정류장 순서 (앱 안 노선 데이터가 없는 지역: 전주·경기·제주·TAGO)
  - 노선 정보 (첫차·막차·배차간격)
  - 정류장 경유노선 (앱 안 데이터가 없는 지역), TSB 시군 확인 결과
  - TAGO 도시 목록, 제주 노선 목록
- 계속 서버를 부르는 것: 실시간(도착·버스 위치·지하철), 전주 길찾기·환승, 기차·고속·항공 시간표.

### 지도의 버스 = GPS 가 있는 API 만

지도에는 GPS 좌표를 주는 API 의 버스만 그립니다 (제주 BIS, TAGO). 위치를 지어내지 않습니다.
전주시 API·경기 GBIS 는 GPS 없이 "몇 번째 정류장"만 줘서 지도에는 그리지 않고, 노선 패널 정류장 목록에 버스 아이콘·차량번호로만 표시합니다.
정류장 순번으로 정류장 사이를 움직이던 추정 방식(정차 20초, 속도 학습, 85% 지점 대기)과 전주에서 TAGO GPS 를 빌려 오던 것은 삭제했습니다.

### 같은 정류장, 번호 여러 개

같은 자리의 다른 시군 정류장 = 전국 정류장 파일(시군마다 가장 가까운 30m 안) + **TAGO 주변 정류장**.
전북 통합 정류장(TSB…) 중 전주시 안의 정류장은 파일에 없어서(예: 기린대로 병무청 30703 ↔ 3050070) 주변 정류장으로 찾습니다.
패널 머리에 번호를 모두 ("30703, 3050070"), 그 정류장에 서는 다른 시군 버스도 같은 목록에 지역 이름과 함께.
각 정류장의 도착·경유노선은 그 지역 API 로 받습니다.

### 노선을 열 때 지도

- **노선 검색**에서 고르면 노선 전체가 보이게 맞춥니다.
- **정류장에서 노선**을 누르면 지도는 정류장을 보던 그대로 둡니다.

### 앱을 열자마자 지도가 뜨도록

- **앱을 켜면 항상 현재 위치 중심**: 휴대폰이 아는 마지막 위치로 바로 이동하고 새 GPS 위치로 보정합니다. 권한이 없으면 처음에 한 번 묻습니다.
  저장해 둔 마지막 지도 자리는 위치를 받기 전까지 잠깐 보여주는 용도. 탭을 바꿨다 돌아오면 보던 자리 그대로.
- **정류장을 누르면 현위치 버튼과 똑같이 그 정류장이 지도 정중앙** (지하철역도 같음).
- **정류장에서 노선·열차 경로를 눌러도 지도는 보던 그대로**. 노선 검색에서 고른 노선과 길찾기 경로만 전체가 보이게 맞춤.
- **노선도 버스 옆 저상 표시**: 위치는 TAGO GPS, 저상 여부는 전주시 API(busLow)를 차량번호로 합침. TAGO 위치 정보에는 저상 여부가 없어 전주 외 지역은 표시 안 됨.
- **지도 타일 보관**: 받은 타일을 앱 저장소(filesDir)에 최대 400MB 보관하고 30일 동안 다시 받지 않습니다. 한 번 본 지역은 열자마자 보입니다.
- **처음 보는 지역**: 타일 동시 다운로드 2개 → 4개.
- **정류장 DB**: 지도 화면이 아니라 앱이 켜지는 순간 준비를 시작합니다.
- 네이버·카카오처럼 자체 지도 서버·벡터 지도를 쓰는 게 아니라 브이월드 타일을 받는 구조라, 처음 가보는 지역은 타일을 받는 시간이 있습니다.

### 열차 경로·패널

- 지도에서 **열차를 누르면** 행선지와 현재 위치, 행선지까지 거치는 역 목록을 보여주고 지도에 경로를 그립니다.
- 역 상세의 실시간 도착에서 **"~행"을 누르면** 그 열차가 지금 있는 역부터 행선지까지 같은 방식으로 보여줍니다.
- 서울 API 가 역 순서를 주지 않아서, 행선지 방향의 다음 역을 반복해서 찾아 순서를 만듭니다 (`StationIndex.pathToward`).
- 아래 패널은 위쪽 손잡이를 위아래로 끌어 높이를 바꿀 수 있고, 놓으면 작게·중간·크게 중 가까운 높이에 맞춰집니다. 손잡이를 누르면 중간↔크게.

### 버스 검색·도착정보 안정화

- **전국 통합 검색**: 지역 선택 없이 전국 도시를 3곳씩 동시에 검색해 찾는 대로 목록에 추가합니다(지역 이름 표시).
  지금 지도에 보이는 지역 → 같은 도 → 나머지 순서. 검색 한 번에 도시 수 × 2~3건을 호출하므로 개발계정 일일 한도에 주의하세요.
- **도착 시간이 떴다 안 떴다 하던 문제**: TAGO 는 동시 요청이 많으면 코드 99(세션 없음)로 거절합니다.
  모든 TAGO 요청을 동시에 4개까지로 제한하고 99 는 잠깐 쉬었다 재시도합니다. 빈 응답은 한 번은 무시하고, 실패하면 직전 정보를 유지합니다.
- 경유노선은 정류소마다 한 번만 받아 새로고침 때 도착정보 한 건만 요청 → 더 빨라졌습니다. 요청 중에는 상단에 진행 막대.

## 구조

```
core/   TagoXml(공통 파서) · TagoTime(시간 포맷) · Fmt · TagoResult/Load      ← 안드로이드 의존성 없음
data/   TagoApi(Retrofit, 전 엔드포인트) · Network · TagoRepository · Mappers · Models

```

기차·항공·고속·시외는 모두 "출발 → 도착 + 날짜 + 등급필터" 구조라 `TimetableController` 하나로 처리합니다.

## PDF 응답에서 확인한 TAGO 특이사항 (코드에 반영됨)

- **응답은 XML로 받음**: JSON은 item 1건일 때 배열이 아닌 객체로 오고 숫자/문자열 타입이 흔들립니다. XML 공통 파서(`TagoXml`) 하나로 전 서비스를 처리합니다.
- **필드명 규칙이 서비스마다 다름**: 기차는 전부 소문자(`depplacename`), 고속은 camelCase(`depPlaceNm`). 지하철은 같은 의미인데 검색 API는 `subwayStationName`, 시간표 API는 `subwayStationNm`. → `Row.str("a", "b")` 대소문자 무시 + 후보 키.
- **시간 포맷 7종**: 항공·고속 12자리, 시외·기차 14자리, 고속도착 `2026-10-09 16:59`·`12:10`, 지하철 `052000`, 버스 `0600`. → `TagoTime` 이 모두 처리.
- **지하철 시간표**: 완전히 같은 행이 반복되어 옴(서울역 05:20이 3번) → 중복 제거. `depTime=000000, arrTime=0` 행은 운행시각이 아니라고 보고 제외. 00~02시 열차는 그날 운행의 연장으로 정렬.
- **기차 운임 0원**: 같은 무궁화호인데 `adultcharge=0` 인 열차(04753)가 섞여 있음 → "요금 정보 없음".
- **항공 편명 필드 오타**: `vihicleId` (vehicle 아님). 매퍼가 둘 다 확인.
- **고속버스 터미널 코드 체계가 두 개**: `ExpBusInfo` 는 `NAEK020`, `ExpBusArrInfo` 는 `500` 같은 숫자 3자리. 서로 호환되지 않아 실시간 탭은 별도 터미널 목록을 씁니다.
- **센트럴시티(서울)** 이 `NAEK020`/`NAEK021` 두 개로 나옴 → 선택 시트에 ID를 함께 표시.
- **열차 차종 ID** `0A` 처럼 숫자가 아닌 값 존재 → 문자열로 처리.
- **코드 목록 API**(등급·차종·항공사)는 `totalCount` 가 없음 → 받은 개수를 전체로 간주.
- `resultCode=03`(NODATA)은 오류가 아니라 빈 목록으로 처리. `<OpenAPI_ServiceResponse>` 게이트웨이 오류는 코드별 한국어 메시지로 변환하고, 키·권한 오류는 페이지 크기 재시도 없이 바로 표시.

## 실기기에서 확인이 필요한 부분

- **고속버스도착정보 파라미터명**: `GetExpBusTmnList` 의 `tmnNm` 은 공식 문서로 확인했지만, `GetArrTmnFromDepTmn` / `GetExpBusArrPrdtInfo` 의 `depTmnCd` / `arrTmnCd` 는 응답 필드명에서 추정했습니다. 다르면 `TagoApi.EXP_ARR_DEP` / `EXP_ARR_ARR` 상수 두 개만 바꾸면 됩니다.
- **터미널 전체 목록**: 고속·시외·고속도착 터미널은 이름 없이 전체를 받아 캐시한 뒤 로컬 검색합니다. 서버가 이름 없는 요청에 빈 목록을 주면 자동으로 이름 검색으로 바뀝니다.
- **지하철 `000000` 제외 판단**: 실제 자정 출발 열차가 있는 노선이면 `Mappers.subwayDeparture` 에서 조건을 조정하세요.
- **공휴일**: 지하철 요일 구분은 요일만 보고 기본값을 정합니다(공휴일 판별 없음). 칩으로 직접 바꿀 수 있습니다.
- 이 환경에는 Android SDK가 없어 Gradle 빌드는 돌리지 못했습니다. `core` + `data` 레이어는 실제 Kotlin 컴파일러로 컴파일했고 `ParserTest` 12개(PDF 응답 픽스처)가 모두 통과했습니다. UI 파일은 구문 검사까지 했습니다.

## TagoTransit 으로 옮길 때

TagoTransit 에 없는 기능은 **고속·시외버스**, **고속버스 실시간 위치**, **TAGO 지하철(서울 외 전국 시간표·출구정보)** 입니다.
`core/` 와 `data/` 는 그대로 복사 가능하고, 화면은 `ui/coach`, `ui/subway`, `ui/timetable` 을 패키지명만 바꿔 붙이면 됩니다.
